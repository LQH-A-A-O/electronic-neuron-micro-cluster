# 修复：按输出形态分组的置信度阈值（2026-10-17）

## 一、根因（已量化）

长测里 `mean_logprob` 判据把**开放式生成**误判成**难题**。根因是：
**写作与代码的 logprob 差 65 倍**，而判据用的是**全局同一份历史**。

| 类别 | logprob 中位 | 范围 | 每 token 概率 |
|---|---|---|---|
| **写作** | **−0.7159** | −0.85 ~ −0.58 | ≈ 0.49 |
| **代码** | **−0.0110** | −0.18 ~ −0.0002 | ≈ 0.99 |

> **写作天然"不自信"——不是因为它难，而是因为每个词都有多种合理选择。**
> 在代码占主导的混合流里，全局阈值被代码的高置信拉低，**写作就永远落在低分位**。

## 二、修复

**按输出形态自分类，每一类维护自己的置信度历史。**

    cls = "code" if 输出里有代码块 else "text"
    阈值 = 该类自己历史的 ESC_FRAC 分位

不需要任务类型分类器、不需要额外模型——**输出形态本身就是分类器**。

## 三、验证（用已采到的 logprob 做忠实重放，不用再跑模型）

长测的 **2:1 混合**（代码主导）：

| 判据 | 写作升级 | 代码升级 |
|---|---|---|
| **修复前**（全局历史） | **12/20（60%）** | 0/20（0%） |
| **修复后**（每类历史） | **4/20（20%）** | 1/20（5%） |

> **写作的无谓升级降了 3 倍（60% → 20%），代码仍接近 0。**
> （长测实测是 74.6%，比这里的 60% 更高，因为长测的流更长、写作生成更长；方向和量级一致。）

## 四、实测延迟（修复后，40 条混合）

| 指标 | 数值 |
|---|---|
| 总升级 | **5/40（12%）** |
| P50 | **2.51 秒** |
| P95 | 8.84 秒 |

## 五、诚实边界

1. **重放用的是同一批 40 条样本**（20 写作 + 20 代码），不是独立验证集。
2. **"修复后 20% 的写作升级"里，有多少是真正该升级的，没测**（写作没有判分）。
3. **分类器是"有没有代码块"**——如果模型用文字描述代码（不写围栏），会被误分成文本类。**没测这种边界。**
4. **每类历史需要预热**：每类前 5 条不升级。混合比例剧变时会有短暂失准。
5. **没有重跑 2 小时长测验证修复后的长期行为** —— 这是下一步。
6. 写作的 logprob 中位 −0.72 意味着**每 token 只有 49% 概率**，这在开放式生成里是正常的，
   但也说明 **mean_logprob 对这类任务本身就不该被用作"难度"信号**。
   更根本的修法可能是**换信号**（比如用最低 logprob、或多次采样一致性），**没做**。
