# 落地：可运行的知识服务（2026-10-18）

## 一、它是什么

`serve.py` —— 一个只用 Python 标准库的 HTTP 服务 + 单页前端。

    GET  /             网页：输入问题，看答案与召回依据
    GET  /api/ask?q=   返回 {answer, verified, abstained, evidence[], ms}
    GET  /api/stats    库状态

**依赖的后端**（已固化在代码里）：

| 服务 | 端口 | 作用 |
|---|---|---|
| 3B Q4 | 8050 | 回答问题 |
| bge-small-zh | 8044 | 向量检索 |
| 本服务 | **8399** | HTTP + 网页 |

## 二、实测请求（真实 curl 输出）

### 1. 库状态
    {"facts": 60, "llm": "http://127.0.0.1:8050", "emb": "http://127.0.0.1:8044"}

### 2. 能答的问题
    GET /api/ask?q=订单服务的监听端口是多少
    {"answer": "8000", "verified": true, "abstained": false,
     "evidence": [{"fact": "订单服务 的监听端口是 8000", "score": 0.9302},
                  {"fact": "报表平台 的监听端口是 8245", "score": 0.7788},
                  {"fact": "支付网关 的监听端口是 8035", "score": 0.764}],
     "ms": 279}

### 3. 库里没有的问题（关键）
    GET /api/ask?q=临时服务X99的端口
    {"answer": "不知道", "raw": "8910", "verified": false, "abstained": true, "ms": 121}

> **模型本来编了 "8910"，可验证性检查发现它不在召回文本里，改答「不知道」。**
> **这就是"不自信地编"和"明确不知道"的区别——落地时最重要的安全属性。**

### 4. 网页
    2474 字节 HTML，深色单页，输入框 + 答案卡片 + 召回依据列表（带相似度分数）

## 三、两个必须记住的工程坑（都是实测踩到的）

| 坑 | 现象 | 解法 |
|---|---|---|
| **端口被旧进程占用** | 8198/8199 上有一批 **2026-10-16 启动的旧 python 进程**在 LISTENING，它们抢先响应，返回 `{"error":"not found"}`，而我的服务明明"就绪"了 | **换端口到 8399**（已确认空闲） |
| **pwsh 不传 workdir** | 默认在 `E:\aqca\work`，找不到 `serve.py` | **必须显式传 workdir** |
| **`--chat-template-kwargs` 的 JSON 被 PowerShell 搞坏** | 3B 启动报 usage 错误、退出码 1 | **Qwen2.5 没有 thinking 模式，直接去掉这个参数** |

## 四、设计约束（来自前面几轮的实测，写进代码注释了）

1. **记忆写入源必须是外部数据**，不接受模型自采样
   —— 实测：用模型自己的幻觉当记录，门控 precision = **0.000**
2. **答案必须在召回文本里找得到依据**，否则弃答
   —— 实测：能把"不可答问题的乱答率"从 **40% 压到 20%**
3. **检索必须用专用 embedding 模型**
   —— 实测：基座 LLM 的 embedding 平均领先为**负**（4/15），bge 是 **87%**

## 五、当前能力（有实测数字支撑）

| 指标 | 数值 | 来源 |
|---|---|---|
| 可答问题准确率 | **80.0% ±7.5%** | 130 条基准 |
| 无记忆时准确率 | **3.6%** | 同上 |
| 不可答时弃答率 | **80%** | 同上 |
| 单次请求延迟 | **121~279 ms** | 本次 curl |

## 六、诚实边界

1. **库里只有 60 条事实**（评测集），没有接真实文档。
2. **没有鉴权、没有限流、没有持久化** —— 是个能跑的原型，不是生产服务。
3. **单进程单线程处理请求**（`ThreadingHTTPServer` 但后端 `-np 1`），并发会排队。
4. **只测了两条 curl**，没有跑完整的 130 条走 HTTP 路径。
5. **网页没有在真实浏览器里验证过交互**（只用 curl 确认了 HTML 返回正常）。
