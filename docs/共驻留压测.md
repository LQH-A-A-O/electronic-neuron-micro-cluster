# 共驻留压测：通过（2026-10-17）

## 一、为什么这是最后一关

3B Q4 + 9B IQ3 = **7481 MiB / 8188 MiB**，只剩 **468~587 MiB** 余量。
这个余量如果一塞长上下文就 OOM，那"共驻留"只是纸面方案。

## 二、实测

| 上下文规模 | 3B-Q4 | 9B-IQ3 |
|---|---|---|
| ~250 token | ✅ 0.5 秒 | ✅ 0.7 秒 |
| ~2000 token | ✅ 0.5 秒 | ✅ 1.1 秒 |
| **~6000 token** | ✅ 1.0 秒 | ✅ 2.3 秒 |

（3B 实际收到 251 / 2051 / 6051 token；9B 收到 214 / 1834 / 5434 token。）

## 三、显存稳定性

| 时刻 | 已用 | 空闲 |
|---|---|---|
| 两个模型启动后 | **7481 MiB** | **468 MiB** |
| 三次压测之后 | **7512 MiB** | **437 MiB** |

> **增长 31 MiB，没有泄漏。468 MiB 的余量足以撑住 8k 上下文。**

## 四、结论

> **推荐配置（3B Q4 + 9B IQ3_XXS 共驻留）在 8192 上下文下可承受。**
> **这是"电子神经元超小集群"在这台机器上第一个通过完整验证的部署形态。**

## 五、诚实边界

1. **只测到 ~6000 token 的提示**，没测到 8192 的上限；**更长的输入没试**。
2. **单流（`-np 1`）**，多并发完全没测。真的多用户场景下 468 MiB 会立刻撑爆。
3. **压测只发了几十个 token 的生成**，长时间连续生成（比如几百轮对话）没测。
4. **没有在压测时同时启动 DSH/浏览器** —— 真实使用时桌面程序会再占显存，
   那时余量可能归零。
5. **只测了 3B 和 9B-IQ3 这一对**，换模型组合要重测。
