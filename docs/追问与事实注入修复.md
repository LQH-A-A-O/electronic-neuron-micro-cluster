# 追问机制 + 事实注入修复（2026-10-18）

## 一、做了什么

### 1. 歧义追问

检测到**两条事实分数接近且都够相关**时，不猜，返回追问：

    {"clarify": true,
     "answer": "你的问题可能指两条不同的记录，请确认是哪一条？",
     "options": [{"key": "...", "text": "...", "score": 0.72}, ...]}

判据：`top1 - top2 < 0.04` 且 `top1 >= 0.55`。

**第二个条件（相关度下限）是必须的** —— 没有它，不可答的问题（所有分数都低但彼此接近）
会被误判成"歧义"，而不是正确弃答。实测踩到了这个坑。

### 2. facts 加中文说明（数据修复）

原来 facts 只有英文 key：`qa130_accuracy = 0.800`，查询「知识问答的准确率」**检索不到**。

改成：

    - `qa130_accuracy` = `0.800`  <-- measured_at: 2026-10-18, n: 110, 说明: 知识问答基准的可答准确率 正确率

加中文说明后，该查询的 top-1 从"错"变成 `qa130_accuracy`（0.7258，领先 0.0816）。

> **教训：检索键必须包含用户会说的词，不能只有内部标识符。**

### 3. 事实只注入 top-1

实测注入 top-3 时，模型会在两条都叫"准确率"的事实里**挑错一条**（检索对、生成错）。
改成只注入 top-1。

|---|---|---|

**8/9 正确。**

## 三、❗ 剩下那 1 个失败值得单独说

「知识问答的准确率是多少」，**检索已经对了**（top-1 = qa130_accuracy = 0.800，领先 0.0816），
**只注入了这一条**，但模型仍然答 **0.81**（那是 `intent_map_accuracy` 的值）。

**也就是：上下文里只有 0.800，模型却输出了 0.81。**

可能原因：

1. **模型把"0.800"读成了"0.81"**（数字相近的生成噪声）
2. **episodes 里恰好有 0.81**，模型从那里取了
3. **提示词里"只回答要点"诱导它简短化**，把 0.800 简写成 0.81

**没查证是哪一种。** 这是"检索对、生成错"的典型案例，也是这类系统最难修的一层。

## 四、修掉的三件事

| 问题 | 修法 | 效果 |
|---|---|---|
| 不可答被误判成歧义 | 追问加相关度下限 0.55 | 幽灵集群正确弃答 |
| 中文查询检索不到英文 key | facts 加"说明"字段 | top-1 变正确 |
| 多事实诱发挑错 | 只注入 top-1 | 大部分题更稳 |

## 五、诚实边界

1. **只有 9 个问题**，8/9 的置信区间约 ±20 个百分点。
2. **剩下那 1 个失败没定位到根因**（三种可能都列了，没查）。
3. **阈值 0.04 / 0.55 是拍脑袋的**，没扫。
4. **只注入 top-1 会丢失"需要比较多条事实"的问题**（比如"级联比单跑高多少"）。
5. **HTTP 服务仍未跑通后台常驻**，以上全部用模块直调验证。
