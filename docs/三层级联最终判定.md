# 三层级联的最终判定：**不成立**（2026-10-17）

## 一、实数据

**3B 采 K=3（全 164 题，820 秒）**：

| 互证度 | 题数 | 占比 |
|---|---|---|
| 0.333（三个解全不同） | **104** | **63%** |
| 0.667（两个一致） | 33 | 20% |
| 1.000（全一致） | 27 | 16% |

- **3B 单采样 pass@1 = 0.652**
- **升级率（阈值 0.34）= 63%**

## 二、🚩 致命的一笔账

| 方案 | pass@1 | **平均延迟/题** |
|---|---|---|
| 3B 单采样 | 0.652 | 6.8 秒 |
| **3B→9B 级联（63% 升级）** | 未知（≤0.77） | **31.9 秒** |
| **9B 直接跑** | **0.768** | **18.0 秒** |

> **级联 31.9 秒/题，而直接把 9B 跑一遍只要 18.0 秒/题。**
> **级联比"直接用更强的模型"慢 77%，而且质量上限还更低（0.768）。**

### 为什么必然如此

**K=3 采样本身就比"直接跑上一层"更贵**：

| 采样开销 | vs 上一层单独跑 |
|---|---|
| 1.5B × K=3 = **13.5 秒** | 3B 单独 = **6.8 秒** → **采样贵 2 倍** |
| 3B × K=3 = **20.5 秒** | 9B 单独 = **18.0 秒** → **采样贵 14%** |

**只要"便宜层 × K" ≥ "贵层 × 1"，级联在成本上就永远输。**
实测两档都满足这个不等式 —— **所以级联在这台机器上结构性不成立。**

这也解释了之前那个异常：**1.5B→3B 级联 18.6 秒 vs 3B 单独 6.8 秒，同分（0.883）但慢 2.7 倍。**

## 三、那"对比决定升级"这个想法就废了吗？—— 不，**是要把对比做成免费的**

问题不在"用对比决定升级"这个思路，而在**我用多次采样来实现对比**。
多次采样是**付费**的（×K），而升级本身只付 1 次。

**正确的做法：用单次推理就能拿到的免费置信信号。**

llama.cpp 的 `/v1/chat/completions` 支持返回 **token logprobs**。
单次推理的平均对数概率 / 最小对数概率，就是**免费的置信度**：

    跑一次 3B  -> 拿 logprobs -> 平均/最小 logprob 低 = 不确定 -> 升级到 9B
    成本：3B 一次（6.8 秒）+ 63% × 9B（11.3 秒）= 18.1 秒  ≈ 和直接跑 9B 持平
    但如果置信信号更准（升级率降到 30%）-> 6.8 + 5.4 = 12.2 秒，才真正划算

> **判据必须免费。** 这是这一轮最重要的教训，而且它给出了明确的修正方向。

## 四、修正后的结论表

| 方案 | 成立? | 理由 |
|---|---|---|
| 1.5B→3B→9B 多采样级联 | ❌ **不成立** | 采样成本 ≥ 直接跑上一层 |
| MoE | ❌ 不成立 | 10~3.4 tok/s |
| **单模型按场景选**（1.5B / 3B / 9B） | ✅ 成立 | 已验证 |
| **logprob 置信度驱动的级联** | ⏸ **待测** | 判据免费，是唯一还有希望的形态 |
| 门控记忆 | ✅ 成立 | P5：0.880 → 1.000，且不增加推理延迟 |

## 五、诚实边界

1. **级联的 pass@1 没测完**（9B 只跑了升级题的一部分，phase2 未跑）。
   但**延迟账已经足以否掉它**：31.9 vs 18.0 秒，质量上限还更低。
2. **阈值只试了 0.34/0.50/0.67**，0.34 与 0.50 结果相同（因为分布只有三个取值）。
3. **logprob 方案完全没测**，能不能拿到、信号准不准都是未知。
4. **K=2 没试**：理论上 K=2 能把采样成本降低 1/3，但两票"一致"的信息量也更弱。
