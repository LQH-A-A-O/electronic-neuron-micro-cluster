# 交付证据包 —— 能不能上线？

> 25 个阶段（含 6 个落地阶段 G1~G6）的最终交付。
> **每一个结论都能追到一份报告、一张图、一个结果 JSON。**

## 一、总判定

> # ❌ 不能上线（T1~T7 后定稿）
>
> **T1~T7 的变化**：
> - ✅ **F23 修好了**：把审计从"只评锚"改成"打到记忆条目上降权"，
>   持续污染下总体 ACC **0.352 → 0.579（+0.227）**，坏锚轮数 28.2 → 0.2。
> - ✅ **D5 的 HILO 缺陷修好了**：连续置信度让 HILO 从开关变旋钮（跨度 0.009 → 0.114）。
> - ❌ **D3 定稿为不通过**：T7 用更稳的判据在 5 个非图像数据集上重跑，
>   优势只有 −0.007~+0.056，**与种子噪声同量级**。（中间那版"条件通过"是被不稳的指标误导的。）
> - 📋 失败模式清单 **21 → 25 条**（新增 F22 捷径噪声、F23 审计惰性、F24 指标脆弱、F25 维度失衡）。
>
> ## 一句话
> **mem-neuron 目前只在图像数据上被验证过**（D1 的"省 84%"全部来自 MNIST 系）。
>
> ---
>
> # 原判定：❌ 不能上线
>
> **理由：D3（不同性质的数据）与 D5（超参敏感度）两条硬标准不通过，
> 而且 D3 的结果把适用边界收窄到了「高维、有结构的数据」。**
>
> 但这不是"这套东西没用"—— D1（省 84% 标注）与 D6（资源账）通过了，
> 它的正确定位是：
>
> **「在标注预算受限、且数据流会被污染的场景里，把有限预算花在刀刃上」——
> 且仅在数据是高维、有结构、头寸足够大的时候。**

## 五、已验证的机制结论（21 条，略去推导）

见 [README.md](../README.md) 全文。最关键的六条：

1. 这套结构的价值 **100% 来自验证器的质量**，不来自层级结构。
2. 验证器的合格线是**漏放率 < 0.5**（与污染率无关，先推公式再实测）。
3. 门控**不产生能力，只转移能力**（预算为 0 时精确退化成无记忆）。
4. **审计该降权不该撤销**；**盖章该降独立度不该删记忆** —— 同一个教训出现了两次。
5. **系统内部没有独立参照**（三个阶段、三种机制撞同一堵墙）——**只有 oracle 独立**。
6. **零 oracle 模式**：完全不花标注也能跑，只掉 0.014。

## 六、要改判定，得先做什么

| 想翻案的判定 | 需要什么 |
|---|---|
| **D3（最难）** | 在**另外 2~3 个**不同性质的数据集（时序 / 文本 / 推荐）上复现"省 ≥30%"。目前的否定结论只有**一个**表格数据点。 |
| D5 | 让两个通道输出**连续置信度**（现在 HILO 是开关不是旋钮），重扫一遍 |
| D2 | 把 oracle 预算往上推，看能不能逼近全标注上界 |
| 整体 | 补一个**不同性质**的数据集是唯一的翻案路径 |

## 七、诚实边界（必须一起交付的）

1. **23 个机制阶段里，绝大多数只用了一两种数据（MNIST 系）**，广度是最后 5 个阶段才补的。
2. **所有"污染"都是人工注入的**（结构化翻转 / 数据源错标），不是真实世界的标注错误。
3. **多种子只有 3~5 个**，标准差常在 0.03~0.08，与部分结论的效应量同量级。
4. **坏锚在阶段 23 里是短暂的**（污染窗口有限），"审计是保险不是收益"这个结论依赖于此。
5. **性能数字来自纯 Python 原型**，绝对值不代表产品。
6. **D3 的否定只有单个数据点**（Covertype）。它足以让我们**不宣称通过**，
   但不足以断言"表格数据一律不行"。
