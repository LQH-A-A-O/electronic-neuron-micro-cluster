# 「自建电子神经元参数库形成模型」可行性评估（2026-10-17）

## 一、先说结论

| 方案 | 判定 | 主要障碍 |
|---|---|---|
| **从零训练一个模型** | ❌ **不可行** | 算力：本机只有 CPU 版 torch；复现 3B 的 0.677 需要 ~3B 参数 + 万亿级 token |
| **自建"参数库"替换预训练权重** | ❌ **已被本次实验否定过** | P4：记忆层**不能减少所需参数量**（目标精度下省 0%） |
| **小模块 + 路由器（MoE 式）** | ⚠️ **本次实测不利** | OLMoE（7B/1.3B 激活、有学习到的路由器）探针 **0.577**，低于 1.5B 稠密 **0.808** |
| **小适配器库（LoRA）+ 对比路由** | ✅ **可行，且是唯一没被否定的版本** | 训练靠 CPU 很慢，只能做玩具规模 |

## 二、为什么"从零造"不行 —— 三个硬数字

1. **对标基准**：本机最好的稠密模型是 3B，HumanEval **0.677**、GSM8K ~0.70。
   要从零达到这个水平，量级上需要 **3B 参数 × 万亿 token** 的训练。
   本机是 **CPU 版 torch**（toolbox 里 torch 2.14.1+cpu），连一个 epoch 都跑不动。
2. **推理侧的墙**：本项目实测，权重在显存里约 **90~111 GB/s**、在内存里只有 **15.4 GB/s**。
   就算训出来，超过 ~7 GB 的模型在这台机器上也只有个位数 tok/s。
3. **架构侧的墙**：**小模块 + 路由器这条路，本轮已经有反例**。
   OLMoE（7B 总参 / 1.3B 激活，带学习到的路由器）质量探针 **0.577**，
   而 1.5B 纯稠密是 **0.808**。**"很多小专家 + 路由器"在同等有效规模下并没有赢过稠密模型。**

## 三、那"电子神经元参数库"有没有能落地的版本？—— 有，是 **LoRA 库**

你原话是：「不直接激活参数，而是依靠神经元架构的对比决定激活哪些参数」。
把"参数"从**整个专家**缩小到**小适配器**，这个构想就变得可运行：

    基础模型（固定，3B 稠密，66 tok/s）
        + 一库小适配器（每个几 MB ~ 几十 MB，就是"电子神经元"）
        + 一个对比路由器（本项目已验证的互证判据）
        → 每次推理只挂 1~2 个适配器

**为什么这个版本有希望**：
- 适配器是**几 MB 级**，一库几十个也只有几百 MB —— **完全装得进显存**，不像 MoE 专家那样撑爆内存。
- llama.cpp **原生支持多 LoRA**（`--lora` 可挂多个并带缩放），不需要改推理引擎。
- 路由器复用我们已经验证过的机制（互证成功组 0.944 vs 失败组 0.619）。
- **参数量不增加**（LoRA 是低秩增量），所以不会撞上 P4 那堵墙。

**这个版本的限制（必须说清）**：
- **训练只能做玩具规模**：CPU 上训 1.5B 的 LoRA 很慢，几百条样本也许能出个 demo，谈不上实用。
- **LoRA 擅长"风格/格式/领域适应"，不擅长"注入新知识"**。
  想让它记住新事实，效果远不如检索（也就是门控记忆那条路）。
- **多个 LoRA 同时挂会互相干扰**，路由错了会掉质量 —— 这正好是需要实测的地方。

## 四、我的建议：三条路按性价比排序

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **1** | **门控记忆 + 3B**（真实知识问答） | 唯一**已被验证有增益**的部件（P5：0.880 → 1.000），且**不加推理延迟** |
| **2** | **LoRA 库 + 对比路由** | 你构想里唯一可运行、且没被本轮实验否定的版本 |
| 3 | 从零训模型 | 算力差 3~4 个数量级，**现在不该碰** |

## 五、诚实边界

1. **本会话从没训练过任何适配器**，上面关于 LoRA 的判断是基于架构推理和 llama.cpp 的功能，
   **不是实测**。
2. **P4 的"省 0% 参数"是在线性判别器 + kNN 那套形态下测的**，不能直接推广到 LoRA。
   但它至少说明"外部记忆替代参数"不是自动成立的。
3. **OLMoE 的 0.577 是 18 题小探针**，噪声很大，只能说"没有显示出优势"，不能断言"MoE 一定更差"。
4. **CPU 训练的实际可行性完全没验证** —— 这是启动 LoRA 路线前必须先测的一件事。
