# 报告 · 阶段 4 —— 换成真实数据（MNIST）之后

## 目的

阶段 1~3 的所有结论都建立在"20 维高斯簇"上。这一阶段只做一件事：**把数据换成真的**，
其余全部不动（同一个 MLP、同一个 Adam、同一个门控、同一批对照组、同一段训练循环），
看哪些结论活下来、哪些死掉。

- 数据：**MNIST 原始 784 维像素**（60000 张训练 / 10000 张测试，本地 npy，不依赖 torch 运行）
- 任务流：5 个任务 × 每任务 2 个新类（共 10 类），class-incremental，测试时不给任务 id
- 模型：784 -> 128 -> 64 -> 动态扩头，400 步/任务
- 噪声：训练流里以概率 p 把标签翻成同任务内的另一个类；留出集/测试集永远干净
- 3 个随机种子

数据来源与预处理：torchvision 只用来下载，之后导出成 npy（`fetch_mnist.py`）；
像素 /255 后按全局均值方差标准化。**所有对照组共用同一份标准化参数**。

## 4A：阶段 1 的结论在真数据上复现了

| 噪声 | A 无记忆 | B 无门控回放 | **C 三层+正确验证器** | D 三层+原演示验证器 | E 只回放干净留出集 |
|---|---|---|---|---|---|
| 0% | 0.193±0.001 | 0.849±0.009 | 0.839±0.008 | 0.868±0.005 | 0.849±0.009 |
| 20% | 0.163±0.003 | 0.663±0.031 | **0.781±0.011** | 0.702±0.026 | 0.784±0.011 |
| 40% | 0.123±0.008 | 0.504±0.022 | **0.721±0.006** | 0.532±0.020 | 0.756±0.024 |

（噪声 40% 时的账本）

| 组 | 遗忘量 BWT | 记忆污染率 | 门控拒收 |
|---|---|---|---|
| B | −0.116 | **0.411** | 0 |
| C | **+0.104** | **0.003** | 1266 |
| D | −0.084 | 0.391 | 0 |
| E | +0.130 | 0.000 | 0 |

![真实 MNIST](../out/stage4_mnist.png)

- **噪声 40% 时 C 比 B 高 0.217（相对 +43%）**，遗忘量从 −0.116 翻成 **+0.104**，污染率 0.003 vs 0.411。
  合成数据上这三条（门控有效 / 增益随污染增长 / 污染率被压到 0）**原样成立**。
- **D 依旧贴着 B**（0.532 vs 0.504）："验证器错了，三层结构就退回无门控回放"这条也原样成立。
- 噪声 0 时 C≈B≈E：门控不花钱。

### 但有一处分歧，得记下来

真数据上 **C 明显低于上界 E**（0.721 vs 0.756，合成数据上两者是打平的）。
也就是说：门控把脏流净化到了"接近"干净池的水平，但**没有完全追平**。
原因大概是：门控在真数据上**误拒太多** —— 噪声 0% 时它就拒掉了 811/2000 = **41%** 的干净条目
（合成数据上是 18%）。根因还是那个老毛病：20 维以上、784 维尤甚，
余弦相似度阈值 0.5 判"同一个类"太严。有冗余数据兜着没翻车，但这是**已经记录在案的待修缺陷**。

## 4B：预算那条结论**没有**迁移过来（本次最重要的负结果）

| 每任务标注 | 累计标注 | C 的 ACC |
|---|---|---|
| 0 | 0 | 0.123±0.008 |
| 20 | 100 | 0.351±0.004 |
| 50 | 250 | 0.539±0.031 |
| 100 | 500 | 0.642±0.017 |
| 200 | 1000 | 0.721±0.006 |
| 参照 B 无门控回放 | 0 | 0.504 |

![真实 MNIST 预算](../out/stage4_mnist_budget.png)

对比阶段 2 在合成数据上的结论（"25 条/任务就远超无门控回放，100 条到顶"）：

- **真数据上 20 条/任务（累计 100）只有 0.351，连什么都不做的 B（0.504）都不如。**
- 要 **50 条/任务（累计 250）** 才刚超过 B。
- 到 **200 条/任务（累计 1000）** 还在涨（0.642 → 0.721），**根本看不到"到顶"**。

**结论：合成数据严重低估了 oracle 的价钱。** 在简单的高斯簇上，几十条标注就能把类边界刻下来；
在真实的 784 维手写数字上，同一个类内部的形态差异大得多，几十条远远不够刻画。
所以"这套架构只要一点点标注"这句话，**只在简单数据上成立**。

唯一原样成立的是那个正确性检查：**预算 0 时 C 精确退化成 A（0.123 vs 0.123）**。

## 诚实边界

1. **噪声仍然是均匀随机翻转**，不是真实幻觉。真实模型的错误是结构化、与输入相关的
   （比如把 4 认成 9，而不是随机认成 7）。这是四个阶段共同的、最大的未解决缺口。
2. **任务流只有 5 个任务 × 2 类**。MNIST 只有 10 个类，要更多的任务就得允许类重复出现，
   那会变成阶段 3 那种设定，与"class-incremental"的经典定义冲突。所以 4A 的曲线比阶段 1 短。
3. **标准化参数用了完整训练集统计量**。这在持续学习里是轻微的"偷看未来"，
   但它对所有对照组一视同仁，不影响组间比较。
4. **4B 只扫到 200 条/任务就走了 256 秒**，没有继续加到 400 去看它到底在哪里饱和。
5. 3 个种子，标准差最大 0.031。

## 如果还要往下走

- **把噪声换成结构化幻觉**：用一个训好的小模型去产生错误标签，或者用真实的人类标注噪声模型。
  这是唯一能把"验证门控"从玩具推到有用的一步。
- **修掉 41% 的误拒**：把余弦换成欧氏距离或先做白化，然后重跑 4A，看 C 能不能追平 E。
- **真数据上的漂移流**：把阶段 3 的冷备问题搬到 MNIST 上（用旋转/加噪版本的同一批数字做"世界漂移"）。
