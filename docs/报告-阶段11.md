# 报告 · 阶段 11 —— 锚审计：冷备里的错误由谁来发现？

## 设计时冒出来的、比原问题更锋利的东西

你的第 4 条是"已知数据也可能有错，所以要单独建立另一套比对验证机制"。
动手前我先推了一遍最坏情况，结果比预想的糟：

> **如果冷备里的错误和脏数据同源**，那么"用新证据反查旧锚"这条路会自己断掉 ——
> 坏锚说"真值是 A"，数据流里的脏样本恰好也是 A，门控看到两边一致就判定这是干净数据，
> **一条真值查询都不会花**。审计池里永远不会有这些区域的真值，被动审计什么都发现不了。
> **系统会自信地错下去。**

## 场景（把这个最坏情况做出来）

- 任务 0 的污染率 0.6，而且脏样本**全部来自同一条错误规则 W_wrong**（不是随机翻）
- 系统启动时被塞进一个锚 = W_wrong，覆盖任务 0 的盒子
- 其余任务与阶段 10 相同（污染 40%）

三组对照：

| 组 | 机制 |
|---|---|
| no_audit | 阶段 10 的 D 组，锚永不被质疑 |
| audit_passive | 用门控**自然花掉**的 side 查询积累审计池，回测旧锚 |
| audit_active | **主动抽检**：不管门控怎么判，每轮对每个锚覆盖区强制取 3 条真值 |

## 结果（5 任务 / 3 seeds）

| 组 | 总体 ACC | **任务 0 区域 ACC** | side 查询（其中强制） | 降级 / 重编译 | 剩余锚 |
|---|---|---|---|---|---|
| no_audit | 0.527±0.082 | **0.023±0.017** | 532 (0) | 0.0 / 0.0 | 5.3 |
| audit_passive | 0.529±0.082 | **0.030±0.022** | 505 (0) | 0.3 / 0.0 | 5.0 |
| **audit_active** | **0.531±0.139** | **0.067±0.012** | 590 (49) | **2.3 / 0.3** | 4.0 |

## 三条发现

1. **同源污染的场景比预想的更糟。** 无审计时任务 0 区域准确率 **0.023**，
   而且全程**一条 side 查询都没花**（强制 = 0）。坏锚和脏数据互相印证，
   门控根本没有"犹豫"过，所以连纠错的机会都不产生。

2. **被动审计几乎完全无效**（0.030 vs 0.023，只降级了 0.3 个锚）。
   原因就是上面那条：门控不在这些区域花查询，审计池里就没有真值。
   **"审计"必须自己主动花钱，不能等门控犹豫时白捡。**

3. **主动抽检能"发现"坏锚，但救不回准确率。**
   降级数从 0.3 提到 **2.3**，任务 0 从 0.023 抬到 **0.067**（3 倍），
   但绝对值仍然不可用；总体 ACC 基本没动（0.527 → 0.531，标准差 0.139）。

   为什么？**审计只处理了锚，没处理被这个坏锚放行的那批脏记忆。**
   那些错误条目早就进了库，还在被检索、还在参与预测。把锚撤了，从犯还在。

## 下一个机制（明确且可证伪）

**污染溯源 + 连带撤回**：用审计查出的问题锚，**回溯它当年放行了哪些记忆**，一并撤回。

实现上有一条记录就能做到：给每条被收下的记忆记下"当时是哪个锚投了赞成票"，
审计判定某个锚有问题时，把所有它投过赞成票的条目一起降级。

预测：任务 0 区域 ACC 应该从 0.067 升到 0.5 以上；总体 ACC 从 0.53 往 0.6+ 走。
如果做完溯源仍然上不去，那就说明**错误一旦进入记忆层就无法用结构手段清除**，
只能靠"重建"——那会是另一个量级的结论。

## 诚实边界

1. **坏锚是人为注入的**（直接把 W_wrong 塞进工具箱）。这对应"上一批知识本身就是错的"，
   但不是"系统自己编译出一个错锚"的完整过程。
2. **重编译几乎没成功**（0.3 次）。原因是审计真值样本太少（几十条）而表达式的自由度不低，
   R² > 0.99 的验收把关太严。换个拟合器（比如带先验的贝叶斯回归）可能好一些 —— 没试。
3. **主动抽检是要花钱的**：590 vs 532 次查询（+11%）。这个代价相对于"发现坏锚"值不值，
   本轮没有做成本-收益的扫描。
4. 任务 0 区域的 0.067 只有 3 个种子、标准差不小（0.012）；总体 ACC 的标准差更是到 0.139。
5. 域仍然是合成的局部多项式，结论不能直接套到真实知识上。
