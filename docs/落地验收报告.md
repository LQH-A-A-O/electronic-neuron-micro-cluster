## 零、一句话结论

**这套东西能落地，但它的定位必须说清楚：**

> 它不是一个「更聪明的模型」，而是一个**「能把外部知识准确搬出来并附上依据的小模型系统」**。
> 没有记忆时它几乎一无所知（**3.6%**）；有记忆时能答对 **80%**；
> 问到库里没有的东西它有 **80%** 会明确说「不知道」而不是乱编。

## 三、三个反直觉的实测结论

### 1. 门控记忆会被「一致幻觉」彻底骗过

用模型自己的幻觉当记录流，门控 **precision = 0.000 / recall = 0.000**。

| 事实 | 真值 | 门控收下 | 票数 |
|---|---|---|---|
| 订单服务 监听端口 | 8000 | **8080** | **5/5** |
| 订单服务 超时毫秒数 | 513 | **300000** | **5/5** |

**漏放率（硬性指标）：**

| 口径 | 定义 | 数值 |
|---|---|---|
| A | 收下的值里有多少是脏的 | **15/15 = 100%** |
| B | 脏记录中"成功闯关"的比例 | **75/143 = 52%** |
| 对照 | 合成随机噪声（P5b）的 A 口径 | **0/600 = 0%** |

> **一个模型的一致性 ≠ 多个来源的一致性。**
> **记忆写入源必须是外部独立数据，不能是模型自采样。**

### 2. 基座 LLM 的隐状态不能当检索向量

| 模型 | pooling | 召回 | 平均领先 |
|---|---|---|---|
| Qwen2.5-1.5B | mean | 4/15 | **−0.0684** |
| Qwen2.5-1.5B | cls | 3/15 | **−0.0491** |
| Qwen2.5-1.5B | last | 4/15 | **−0.0904** |
| **bge-small-zh** | **cls** | **13/15** | **+0.0503** |

> **平均领先为负 = 不是在弱区分，是在往反方向指。**
> **必须用专用检索模型，26 MB 就够。**

### 3. 真实文档的失败主因是「冗余 + 版本冲突」，不是检索算法

| 现象 | 数值 |
|---|---|
| 同一个值 `0.677` 出现在 | **23 个切片** |
| 同一指标的历史值 | 0.883（60 题）→ 0.738（164 题）→ 0.768（9B 单跑） |
| 按文件 mtime 加权 | ❌ **完全无效**（文档同一天写，且冲突在同一文件内） |
| 加关键词混检 | ✅ 60% → 70% |
| 剩余 3 个 MISS | **全是数值冲突，关键词也一样** |

> **知识库最大的敌人不是「查不到」，而是「同一个事实有 23 个副本，一半是旧版本，看起来完全一样」。**
> **修法：① 去重；② 权威性元数据（primary/reference）；③ 数值指标走结构化表，不要塞进文档切片。**

### 4. MoE 在这台机器上没有立足点

| 配置 | 显存 | tok/s |
|---|---|---|
| MoE `-cmoe`（专家全 CPU） | 4227 MiB | **1.0** |
| MoE `-ncmoe 0`（专家全推 GPU） | 7440 MiB | **3.4** |
| 3B 稠密 | ~2500 MiB | **66** |
| 9B-IQ3 稠密 | ~4000 MiB | **23~28** |

> **用满显存也只有 3.4 tok/s，比 3B 稠密慢 19 倍。而且共享显存不算容量（带宽等于内存）。**

## 七、怎么用

```bash
# 1. 起后端
llama-server -m Qwen2.5-3B-Instruct-Q4_K_M.gguf -c 4096 -np 1 -fa on --jinja \
             --temp 0 -ngl 99 --port 8050

             --embeddings --pooling cls -ngl 99 --port 8044

```
