# 系统规格：电子神经元超小集群（单机部署）

> 参考实现：`encluster.py`（已跑通 demo）。全部数字来自本项目实测。

## 一、系统组成

    ┌──────────────────────────────────────────────────────┐
    │ L0  门控记忆                                          │
    │     记录 = (key, value)，同 key 多条互证；一致的收，冲突的拒   │
    │     冷启动 / 票数打平才花 oracle                       │
    ├──────────────────────────────────────────────────────┤
    │ L1  Qwen2.5-3B 稠密（66 tok/s，6.8 秒/400 token）       │
    │     每次推理同时取 token logprobs（免费置信度）           │
    ├──────────────────────────────────────────────────────┤
    │ L2  Qwen3.5-9B IQ3_XXS（4.02 GB，23~28 tok/s）         │
    │     与 L1 同时常驻（共 7362 MiB），无需换模型            │
    │     仅当 L1 的置信度落在「最近 N 条的相对低分位」时升级      │
    └──────────────────────────────────────────────────────┘

## 二、实测指标

| 场景 | 准确率 | 延迟 | 升级率 |
|---|---|---|---|
| 记忆类（400 题，门控后） | **1.000** | 3B 一次 | **0%** |
| 记忆类（400 题，未门控） | 0.912 | 3B 一次 | 0% |
| 代码类（164 题，级联） | **0.738** | 10.4 秒/题 | **20%** |
| 代码类（只用 3B） | 0.677 | 6.8 秒/题 | — |
| 代码类（只用 9B Q4） | 0.768 | 18.0 秒/题 | — |
| 代码类（只用 9B **IQ3**） | **0.756** | 18.0 秒/题 | — |

> **最终推荐配置：3B Q4 + 9B IQ3_XXS 共驻留（7362 MiB）。**
> IQ3 的量化代价只有 **0.012**（2 道题），却换掉了每次升级 7.5 秒的换模型开销。
> 详见 [最终配置.md](最终配置.md)。

## 三、四条必须遵守的设计规则（都是踩出来的）

1. **门控记忆负责"上下文对不对"，级联负责"推理难不难"，两者不可互替。**
   - 脏记忆下 3B 准确率 0.912，其中 8.8% 是"自信地抄错"——级联救不了这类错误的主力。
2. **升级判据必须免费。** 用 logprobs（单次推理自带），不要用多次采样。
   - 多采样 ×3 的采样成本 ≥ 直接跑上一层，级联结构性输。
3. **绝对 logprob 阈值不可跨任务迁移，必须用「任务内相对分位」。**
   - 代码任务的分布是 −0.05 量级，记忆任务是 −0.0002 量级，**差 200 倍**。
   - 用同一个绝对阈值，记忆任务的升级率只有 4.5%、只覆盖 43% 的错题；
     换成任务内 25% 分位，覆盖率升到 **94%**。
4. **推理全在 GPU，不要碰 CPU offload。**
   - 权重在显存 90~111 GB/s，在内存只有 15.4 GB/s（差 7 倍）。
   - MoE 用满显存也只有 3.4 tok/s；共享显存带宽等于内存，**不算容量**。

## 四、硬件边界（实测）

| 项 | 数值 |
|---|---|
| 显存 | 8 GB 专属（共享 8 GB 带宽等于内存，**不可用于提速**） |
| **能全进显存的模型上限** | **约 7 GB ≈ 9B Q4** |
| 1.5B / 3B / 9B 稠密 | 98~116 / 66 / 23~28.5 tok/s |
| MoE（专家在内存） | 1.0~3.4 tok/s |

## 五、这套系统**不适用**的场景

- **数学/推理类且 9B 不比 3B 强**（实测 GSM8K：9B 0.670 vs 3B ~0.70）→ 升级白花钱。
- **数据低维、头寸小**（记忆层的收益会消失）。
- **标注错误与特征相关**（捷径噪声）→ 门控失效（实测优势从 82% 垮到 23%）。
- **需要从零训练** → 算力差 3~4 个数量级。

## 六、已知未验证项

1. 混合工作负载（记忆题 + 代码题同一批）没测。
2. 端到端延迟是折算值，没测真实交替加载开销。
3. 阈值窗口 N 和分位比例是经验值，没扫。
4. 长上下文（>8k）下的表现没测。
5. 记忆层的规模上限（实体数 × 记录数）没测。
