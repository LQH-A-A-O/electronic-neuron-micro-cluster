# 记忆能救写作吗：实测（2026-10-18）

> 用户的问法：用上昨天加的笔记功能（.memory/），写作能到什么程度？

## 一、先说结论

| 记忆能做的 | 记忆做不到的 |
|---|---|
| ✅ **提升结构覆盖**（4/4 vs 3/4） | ❌ 写更多字（685 vs 682，一样） |
| ✅ **给它具体材料**（§四，最有价值） | ❌ 改善文笔 |
| ✅ 保证跨节不矛盾 | ❌ 消除「正确的废话」 |
| | ❌ 提升推理 |

## 二、实测：分节生成，有记忆 vs 无记忆

同一份 4 节大纲（为什么需要外部记忆 / 记忆层的设计 / 可验证性检查 / 实测数据与局限），每次只写一节，200 字。

| | A 无记忆 | B 有记忆 |
|---|---|---|
| 总字数 | 685 | 682 |
| **覆盖大纲** | **3/4** | **4/4** |
| 单节内重复 | 0.0% | 0.4% |
| 跨节最高重叠 | 0.0% | 0.0% |
| 用时 | 6 秒 | 6 秒 |

### 结论 1：分节本身就能消除重复

**跨节重叠都是 0.0%**。之前单次生成 3000 字时重复率 13.5%→28.3%，
**分节后完全没有了** —— 所以「长文重复」的解法是**分节**，不是记忆。

### 结论 2：记忆小幅提升结构覆盖（3/4 → 4/4）

因为记忆里存了「已经写了哪几节、要点是什么」，模型知道还缺哪节。

### 结论 3：但记忆引入了提示词泄漏

B 组的输出变成了：

    第 2 节「记忆层的设计」要点：记忆层的设计旨在高效管理数据的存储与访问……

**模型把指令当内容写出来了。** 需要单独处理（后处理剥离，或改用更隐晦的上下文给法）。

## 三、🚩 但真正的问题不是重复，也不是结构

看四节的实际内容：

> 第 1 节：「在当前的计算环境中，内部存储通常受限于有限的内存和存储资源，难以满足大规模、长时间运行的…」
> 第 2 节：「记忆层的设计是确保外部记忆高效、稳定的关键。设计时需要考虑数据的存储格式、索引结构以及访…」
> 第 3 节：「在设计外部记忆系统时，进行可验证性检查至关重要。这包括确保数据的准确性和完整性…」

**全是「需要考虑 X」「要确保 Y」「至关重要」——正确的废话。**

**模型不缺结构，不缺篇幅，缺的是「具体内容」。**

## 四、这才是记忆真正能救写作的地方

**把具体事实喂进去，它写的就不是空话。**

| 没有材料 | 有材料 |
|---|---|
| 「记忆层的设计至关重要，需要考虑存储格式和索引结构」 | 「记忆层用 bge-small-zh（26 MB）做向量化，512 维，1 万条事实检索 0.05 ms」 |

**后者才是能用的内容。**

所以给写作场景配的 facts.md 应该是**素材库**，不是**知识点库**：

```markdown
- `案例-1` = `某团队 9 月用 3B，延迟 0.12 秒；10 月加 9B 级联，延迟 0.70 秒，准确率 0.677→0.738`
- `数据-1` = `6 小时压测 121,428 条，P50 0.125 秒，P95 0.175 秒`
- `引语-1` = `知识不需要同时在场，只需要用的时候能取到`
```

**每写一节，先检索 3 条相关素材注入，再让它展开。**

## 五、给写作场景的正确工作流

    1. 建一个「素材库」（facts.md）：数据、案例、引语、术语定义
    2. 让它先输出大纲（分几节）
    3. 每节生成前：用本节标题检索 top-3 素材 -> 注入
    4. 每节单独生成，200~400 字
    5. 人工串联 + 润色

**这个流程下，记忆的作用不是「教它怎么写」，而是「给它料」。**

## 六、诚实边界

1. **只有 4 节 685 字**，样本极小。
2. **没有测试「注入素材」这条路线** —— §四 是推断，不是实测。
3. **没有人工评价文笔**。
4. **「正确的废话」是我的主观判断**，虽然内容确实空泛。
5. **提示词泄漏只出现了 1 次**（4 节里 3 个），是否普遍未知。
6. **temperature = 0.7**。
