# 部署手册：神经元知识服务（本机）

> 实测环境：RTX 4070 Laptop 8 GB 显存 / 16 GB 内存 / Windows

## 一、你需要什么

| 项 | 规格 | 实测占用 |
|---|---|---|
| 基座模型 | Qwen2.5-3B-Instruct-Q4_K_M.gguf | 2.0 GiB 显存 |
| 检索模型 | bge-small-zh-v1.5-q8_0.gguf | 26 MB |
| 可选：升级模型 | Qwen3.5-9B-UD-IQ3_XXS.gguf | 4.02 GB |
| 推理引擎 | llama.cpp（b9637 或更新） | — |
| Python | 3.12 + requests + numpy | — |

**三个模型共驻留约 7481 MiB / 8188 MiB**（含 9B）。只用 3B + bge 时余量充足。

## 二、三步启动

### 1. 起基座模型

    llama-server.exe -m Qwen2.5-3B-Instruct-Q4_K_M.gguf ^
      -c 4096 -np 1 -fa on --jinja --temp 0 -ngl 99 --port 8050

> ⚠️ **Qwen2.5 不要加 `--chat-template-kwargs`** —— 它没有 thinking 模式，
> 而这串 JSON 在 PowerShell 里容易被引号搞坏，导致启动失败。

### 2. 起检索模型

    llama-server.exe -m bge-small-zh-v1.5-q8_0.gguf ^
      -c 1024 -fa on --embeddings --pooling cls -ngl 99 --port 8044

> ⚠️ **`--pooling cls` 必须加**，且**必须用 bge 这类专用检索模型**。
> 实测：基座 LLM 的 embedding 平均领先为负（召回 27%），bge 是 87%。

### 3. 起服务

    cd E:\aqca\work\mem-neuron
    python serve.py

    -> http://127.0.0.1:8399/

## 三、验证是否正常

    curl "http://127.0.0.1:8399/api/stats"
    # 期望：{"facts": 60, "llm": "http://127.0.0.1:8050", "emb": "http://127.0.0.1:8044"}

    curl "http://127.0.0.1:8399/api/ask?q=临时服务X99的端口"
    # 期望：{"answer": "不知道", "abstained": true}

## 四、排错表（都是实测踩过的）

| 症状 | 真因 | 解法 |
|---|---|---|
| 服务日志说「就绪」但请求是旧行为 | **Windows 允许两个进程绑同一端口**（`SO_REUSEADDR`），旧进程抢连接 | 见下方「端口杀不掉」一节 |
| **端口杀不掉**（`taskkill /F /PID`、`Stop-Process -Id` 都执行了，`netstat` 仍显示 LISTENING） | 实测遇到过：进程处于不可中断状态，或有句柄泄漏 | **别纠缠，直接换端口**（改 `serve.py` 的 `PORT`）—— 换端口比杀进程可靠得多 |
| 启动报 usage 错误、退出码 1 | `--chat-template-kwargs` 的 JSON 被 shell 搞坏 | 去掉该参数 |
| `can't open file serve.py` | pwsh 默认工作目录不是项目目录 | `Set-Location` 或传 workdir |
| 答案全是「不知道」 | `supported()` 误杀，或 bge 没起来 | 查 `--pooling`、查 8044 的 /health |
| 模型加载失败 | 显存被别的进程占满 | `nvidia-smi` 看占用；关浏览器/QQ/Steam |
| 上下文超过 20k 后行为异常 | llama.cpp 显存不足会**静默缩上下文** | 别设超过 32k；要长文档走检索 |

## 五、怎么加自己的知识

编辑 `data/qa_bench.json` 的 `facts` 数组，每条是：

    {"key": "订单服务 的监听端口是 8000", "value": "8000"}

**key 写成一句自然语言**（不是关键词），因为检索是按句子匹配的。

> ⚠️ **重要：记忆的写入源必须是外部数据**（文档、日志、人工录入）。
> **绝对不要把模型自己的输出当成记录写进库** —— 实测门控会被"一致幻觉"骗过，
> precision = 0.000。

## 六、实测性能（可直接引用）

| 指标 | 数值 |
|---|---|
| 可答问题准确率 | **80.0% ±7.5%**（110 条） |
| 不可答时弃答率 | **80%**（16/20） |
| 单次延迟 P50 | **0.127~0.130 秒** |
| 单次延迟 P95 | **0.179 秒** |
| 检索延迟（1 万条） | **0.05 ms** |
| 建索引（1 万条） | 143 秒（一次性） |

## 七、已知限制

1. **单流**：`-np 1`，并发请求会排队。
2. **没有鉴权**：别暴露到公网。
3. **数据不持久化**：facts 从 JSON 读，改完要重启。
4. **上下文 20k 上限**：长文档必须先切分再入记忆库。
5. **判分/校验是字符串匹配**：语义等价的答案可能被判错。
