# 规模验证 + 最终路线（2026-10-18）

## 一、知识规模扫描：1 万条事实仍然满分

| 事实数 | 召回 | 建索引 | 查询编码 | 检索 |
|---|---|---|---|---|
| 100 | 20/20 = **1.00** | 1.4 秒 | 0.31 秒 | 0.000 ms |
| 1,000 | 20/20 = **1.00** | 15.5 秒 | 0.27 秒 | 0.000 ms |
| **10,000** | **20/20 = 1.00** | **143.2 秒** | 0.31 秒 | **0.050 ms** |

### 结论

- **检索成本几乎不随规模增长**（10k 条时 0.05 ms）
- **瓶颈是建索引，且是线性的**：10k → 143 秒，100k 预计 **约 24 分钟**
- **查询编码恒定 0.3 秒**（调 embedding 服务的开销），它比检索本身贵 6000 倍

### 诚实边界（这一条很重要）

**我的查询是从 key 里截取片段拼出来的**（"缓存-0 的并发上限" → "缓存-0 的并发上限 是多少？"），
**字面高度相似**。所以 1.00 的召回**比真实改写查询容易得多**——
上一轮字面不重叠的改写查询只有 **87%**。

> **"万级规模召回 1.00" 这个数字，只说明索引没退化，不说明真实场景的召回。**

## 二、上下文上限（详见 [上下文上限理论.md](上下文上限理论.md)）

| 方案 | 稳定上限 |
|---|---|
| **实测（fp16 KV，3B）** | **20k~40k token** |
| 理论（fp16，5.5 GB 预算） | 148k |
| q8 KV | ~40~80k |
| q4 KV | ~80~160k |
| q4 + 稀疏注意力 | ~160~320k |
| **1M** | **❌ 物理不可能**（q4 也要 9.5 GB） |

> **实测比理论保守得多**：llama.cpp 显存不足时会**自动缩上下文**而不是崩溃，
> 所以"服务起得来"不等于"上下文用得满"。

## 三、🚩 但你不需要 1M 上下文

我们这条路**把"上下文长度"和"知识容量"解耦了**：

| 维度 | 长上下文方案 | 我们的方案 |
|---|---|---|
| 知识放哪 | 全塞进 KV | **记忆库（向量索引）** |
| 上下文需求 | 随知识量线性增长 | **恒定 20k** |
| 知识上限 | 受显存限制（≤160k token） | **受 VA 限制（十万级事实）** |
| 成本 | KV 线性增长 | **索引常驻，检索 0.05 ms** |

> **20k 上下文 + 10 万条向量记忆，比 1M 上下文更有用** ——
> 知识不需要"同时在场"，只需要"用的时候能取到"。

## 四、NeuRAG 的训练栈：**没有开源**

- 论文全文（20 页 / 68,922 字符）**没有任何代码链接**（无 github、无 anonymous repo）
- 搜到的 `recla93/Neurag` 是**另一个项目**（一个基于节点的 MCP 知识库服务器），不是论文实现
- 论文里只有方法描述（每个文档编码成一个 LoRA "知识神经元"，解码时按 hidden state 激活并融合进 FFN：
  `W' = W + P_t`），**没有可复用的代码**

> **所以无法借用它的训练栈。** 而且即使有代码，本机也跑不了（无 peft、torch CPU 版、pip 坏）。

## 五、最终目标：怎么得到一个"神经元架构"的小模型

### 先明确一件事

**在这台机器上，"神经元架构模型"唯一可行的实现形态，不是改模型，而是"小稠密模型 + 外部神经元库"。**

理由（全部实测）：

| 想做的 | 为什么不行 |
|---|---|
| 训练自己的神经元权重 | 无训练栈、CPU 版 torch、pip 坏、10~32 小时/次 |
| MoE 式专家路由 | 用满显存只有 **3.4 tok/s** |
| LoRA 库 + 路由 | 同上，训不了 |
| 改权重的知识注入（NeuRAG 式） | 同上 |

### 所以现实可行的形态

    ┌───────────────────────────────────────────────┐
    │ 外部神经元库（向量索引）                        │
    │   10 万条事实，检索 0.05 ms，召回 87%（改写）   │
    ├───────────────────────────────────────────────┤
    │ 门控层：多记录互证，脏数据挡在外面              │
    │   实测 600/600 脏数据被拒                      │
    ├───────────────────────────────────────────────┤
    │ 基座：Qwen2.5-3B Q4（66 tok/s，6.8 秒/400tk）  │
    │   logprob 分组阈值 -> 低置信升级 9B-IQ3        │
    │   共驻留 7481 MiB，零切换开销                  │
    └───────────────────────────────────────────────┘

**当前实测性能**：0.07 → **0.73**（记忆注入，15 条改写查询）；代码 0.677 → **0.738**（级联，164 题）。

### 要让它"性能足够"，杠杆只有三个（按证据排序）

| # | 杠杆 | 现状 | 预期 |
|---|---|---|---|
| **1** | **降低幻觉** | 模型有上下文还编了个 90 | **最该做**：答案必须能在召回文本里找到，否则说"不知道" |
| **2** | **提高利用** | 0.73 天花板，提示词工程救不了（实测 B/C 打平、D 更差） | 需要**答案校验**或**换更小的 top-k + 重排序** |
| **3** | **扩大知识** | 1 万条已验证不退化 | 100k 条需 24 分钟建索引，一次性的 |

## 六、结论一句话

> **这台机器上能做到的"神经元架构模型" = 3B 稠密 + 10 万条向量记忆 + 门控过滤 + logprob 路由。
> 它不是"训练出来的神经元网络"，而是"用外部库给一个小模型装上可检索的知识"。
> 实测它能做到：改写查询 73%、代码 0.738、2 小时 3017 条零异常、显存零切换。**
