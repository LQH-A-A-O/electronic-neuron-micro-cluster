# 0.81 的根因：模型把自己的错误写进了记忆，然后反复读到（2026-10-18）

## 一、怎么查的（零 GPU）

没跑模型，直接 grep 记忆文件：

    $ grep -n "0\.81" .memory/facts.md
    25:- `intent_map_accuracy` = `0.81`   <-- 意图映射的准确率     ← 这是真事实

    $ grep -n "0\.81" .memory/episodes.md
    51:- 回答：intent_map_accuracy = 0.81
    71:- 回答：intent_map_accuracy = 0.81
    72:- 事实：intent_map_accuracy = 0.81
    82:- 事实：intent_map_accuracy = 0.81
    106:- 回答：intent_map_accuracy = 0.81

**5 处**，全是我前面几轮测试时模型答错的记录。

## 二、根因：幻觉回灌（hallucination feedback loop）

流程是这样的：

    测试轮 1：问「知识问答的准确率」-> 检索不准 -> 模型答 0.81（错）
             -> 服务自动写入 episodes.md：- 回答：intent_map_accuracy = 0.81
    测试轮 2：再问同一个问题 -> 检索到"最近对话"里有这条
             -> 模型看到自己上次说 0.81 -> 照抄 0.81
    测试轮 3、4、5：同样 -> 记忆里堆了 5 条同样的错误

**即使后面把检索修对了、facts 里明明写着 0.800，模型还是被自己的历史带偏。**

## 三、这和之前那个发现是同一个病

| 场景 | 表现 |
|---|---|
| **门控记忆**（外部知识） | 模型 5 次采样都给 300000，门控投 5/5 票通过 → precision = 0 |
| **对话记忆**（本轮） | 模型把错答案写进 episodes，下次读到再重复 → 自我强化 |

> **同一个原则：模型的输出不能无条件当作"记忆"。**
> **记忆是有权威性的，写进去的东西会被当成事实。**

## 四、修法（三条，按必要性）

### 1. 只写"已验证"的答案

    if ok:     写 "- 回答：{ans}"
    else:      写 "- 回答：【未验证】{ans}（依据不足）"

或者干脆**不写答案，只写"用户问了什么"**——因为问题是真的，答案是模型的猜测。

### 2. 不把答案当"事实"写

现在的 episodes 里有 `- 事实：intent_map_accuracy = 0.81`，
那是我拿召回结果拼的，但**召回错了就污染事实层**。

**应该写召回原文（带 key），而不是模型加工后的答案。**

### 3. 记忆里要有"待确认"状态

未验证的回答标记为 `pending`，**检索时降权或排除**，等确认后再转正。

## 五、为什么这一条比修检索更重要

**检索错了，一次答错，修了就完事。**
**记忆污染了，会一直错下去，越错越自信。**

> **这类系统最危险的对手不是"查不到"，是自己之前编过的答案。**

## 六、诚实边界

1. **是 grep 出来的，没有跑模型复现一遍**（GPU 被你游戏占着，没动）。
2. **5 条污染记录都在我测试期间写入的**，实际部署中会持续累积。
3. **没验证"修了写入逻辑后 0.81 会不会消失"** —— 需要清掉旧记录再测。
4. **`episodes.md` 现在有 177 行**，其中相当部分是测试产生的噪声。
