# 混合检索：真实文档 60% → 70%（2026-10-18）

## 一、做了什么

在向量相似度上加一个**关键词覆盖率**项：

    score = cosine(query, chunk) + λ × |关键词交集| / |查询关键词|
    关键词 = 英文标识符 + 数字（HumanEval、bge、0.677、P95…）

## 二、结果

| λ_kw | top-3 含正确答案 |
|---|---|
| 0（纯向量） | **6/10 = 60%** |
| **0.02** | **7/10 = 70%** |
| 0.05 | 70% |
| 0.10 | 70% |

**救回来的是「3B 模型的 HumanEval 是多少」** —— 纯向量时 MISS，
加上关键词（`3B` + `HumanEval` 同时出现）后命中。

## 三、为什么关键词这一项有用

真实文档里的问题是**「实体 + 指标」的组合**：

| 问题 | 关键实体/指标 |
|---|---|
| 3B 模型的 HumanEval | `3B` + `HumanEval` |
| bge 向量检索的召回率 | `bge` |

纯向量会匹配"语义相近"的段落（比如任何讨论 HumanEval 的地方），
**但关键词能锁定"同时提到这个实体和这个指标"的那一段**。

## 四、还剩 3 个 MISS，而且它们说明修复的边界

| 问题 | 正确值 | 为什么混合检索也救不了 |
|---|---|---|
| 1.5B→9B 级联 pass@1 | **0.738** | 语料里同时有 0.883 / 0.738 / 0.768，**关键词完全一样** |
| 共驻留显存 | **7481** | 同时有 7362 / 7481，**都是数字，都相关** |
| 6 小时压测 P95 | **0.181** | 只有 1 个切片有它，但被 179 / 0.128 那批挤掉 |

> **关键词能解决"哪个段落提到了这个词"，解决不了"同一个指标有多个历史值"。**
> 后者**必须靠权威性元数据**（哪份是原始报告、哪份是引用、谁 supersedes 谁），
> **没有别的捷径。**

## 五、三步修复的进展

| 修法 | 状态 | 效果 |
|---|---|---|
| ① 按文件新旧加权 | ❌ 试过，无效 | 文档同一天写、且冲突在同一文件内 |
| ② **混合检索（向量+关键词）** | ✅ **已实现** | **60% → 70%** |
| ③ 去重 | 未做 | 预计对"23 个副本"有效 |
| ④ 权威性元数据 | 未做 | **唯一能解决数值冲突的办法** |

## 六、对落地的建议（更新）

**知识库分两层建**：

1. **叙述性知识** → 文档切片 + 向量检索 + 关键词（本轮的混合检索）
2. **数值型指标** → **结构化表**（`{metric, value, n, measured_at, supersedes}`），
   检索时直接精确查，不要走相似度

> **把"会变的值"和"不变的道理"分开存，是这套系统真正落地的前提。**

## 七、诚实边界

1. **只有 10 个问题**，60%→70% 就是 1 道题，**在噪声内**，不能当显著提升。
2. **λ 没有细扫**（只试了 0.02/0.05/0.10，三者结果相同）。
3. **关键词提取用的是正则**，对中文分词无能为力（只抓英文和数字）。
4. **没做去重**，所以 23 个副本的问题还在。
5. **没接进 serve.py**，只是离线验证。
